# 일일 원고 형식

편집 단계(`docs/editor-routine.md`)가 쓰는 `post.md`는 데스크 단계를 거쳐 `src/content/blog/D-daily.md`로 옮겨진다. 사이트(Astro)가 frontmatter를 스키마(`src/content.config.ts`)로 검사하므로 형식이 틀리면 빌드가 깨진다. 완성 예시는 `src/content/blog/`의 최근 일일 글이다. 전날 글을 열어 구성과 문체를 따라가면 된다.

## 차례
1. frontmatter
2. front (1면 데이터)
3. 본문 섹션
4. 마크다운 규칙
5. tracking.json
6. desk-report.md

## 1. frontmatter

```yaml
---
title: "9월 18일 — 연준 충격 하루 만에 되돌린 뉴욕, 미 10년물 다시 5% 아래로"
description: "두세 문장 요약. 목록·홈·검색 결과에 보인다."
pubDate: 2026-09-18
tags: ["일일", "금리", "시장", "에너지", "지정학", "테크", "부동산"]
front:
  ...
---
```

- `title`: `"M월 D일 — 헤드라인"`. 헤드라인은 `front.headline`과 같게 쓴다. 검색 결과 제목은 사이트가 따로 만든다(CLAUDE.md "사이트 구조").
- `pubDate`: D (따옴표 없이 `YYYY-MM-DD`).
- `tags`: 첫 태그는 반드시 `"일일"`이다. 나머지는 그날 다룬 주제 태그로, `금리` `시장` `에너지` `지정학` `테크` `부동산` 중에서 고른다. 새 주제 태그가 꼭 필요하면 desk-report에 적는다.
- `updatedDate`, `corrections`, `period`, `highlights`, `searchTitle`은 새 일일 글에 쓰지 않는다.

## 2. front — 1면 데이터

```yaml
front:
  headline: "연준 충격 하루 만에 되돌린 뉴욕, 미 10년물 다시 5% 아래로"
  analysis:
    - lead: "금리를 떠받친 힘이 하나가 아니었다."
      text: "두세 문장(100~180자). lead의 결론을 받치는 사실과 그 뜻."
    - lead: "..."
      text: "..."
    - lead: "..."
      text: "..."
  markets:
    asOf: "9월 17일 종가·정산가 · 미국은 현지 시각"
    rows:
      - { name: "코스피", value: "6,715.41", change: "-0.04%" }
      - { name: "원/달러", value: "1,382.2", change: "+13.6" }
      - { name: "S&P 500", value: "7,637.76", change: "+1.14%" }
      - { name: "미 10년물", value: "4.939%", change: "-0.081%p" }
      - { name: "브렌트", value: "$104.82", change: "-0.95%" }
      - { name: "금", value: "$4,399.70", change: "+0.28%" }
  schedule:                         # 없어도 된다. 있으면 한두 개
    - { when: "9/30(수) 21:30", title: "미국 8월 개인소비지출(PCE) 물가", prev: "7월 3.7%, 근원 3.3%", url: "https://www.bea.gov/news/2026/personal-income-and-outlays-july-2026" }
  desks:
    - key: rates
      items:
        - title: "짧은 제목"
          text: "한두 문장."
          source: "매체명"
          url: "https://기사 주소"
        - ...
      summary: "그 데스크의 요약 두세 문장."
    - key: energy
    - key: geo
    - key: tech
    - key: etc
```

- **headline:** 40자 안팎. 그날의 가장 큰 흐름을 담는다. 같은 날 나란히 일어난 두 사실을 원인과 결과로 묶지 않는다.
- **schedule:** 1면 "오늘 볼 일정". 규칙은 CLAUDE.md "일정"과 `docs/editor-routine.md` 4단계에 있다.
- **analysis:** 세 갈래가 기본이다. `lead`는 굵게 보이는 한 문장 결론이고, `text`는 그 결론을 받치는 두세 문장(100~180자)이다. 검증 과정은 쓰지 않는다.
  - 금리, 에너지·지정학, 한국 시장처럼 서로 다른 축으로 나누면 좋다.
  - 사실은 본문에 링크가 있는 것만 쓴다.
- **markets.asOf:** 새 마감이 없는 날(일요일·월요일)은 `· 직전 거래일`을 덧붙인다. 예: `"9월 18일 종가·정산가 · 직전 거래일 · 미국은 현지 시각"`. 휴장한 시장이 있으면 `· 국내는 추석 휴장이라 9월 23일 종가`처럼 밝힌다.
- **markets.rows:** 이 여섯 개를 이 순서로 고정한다. 날마다 같은 칸이어야 독자가 비교할 수 있다.
  - 코스피, 원/달러, S&P 500, 미 10년물, 브렌트, 금.
  - 모두 종가이고, 유가·금은 선물 정산가다.
  - 기준금리(한국·미국)가 바뀐 날만 맨 앞에 `기준금리` 행을 더한다.
  - 값을 아예 구하지 못한 지표만 `value: "—"`, `change: ""`로 둔다.
  - 휴장한 시장(추석·설·공휴일)은 직전 거래일 종가를 값으로 싣고 등락은 비운다. 예: `{ name: "코스피", value: "7,080.92" }`
  - 종가가 아니거나 기사마다 갈린 값은 기준을 밝혀 싣고 등락은 비운다. 예: `{ name: "미 10년물", value: "5.16~5.20%" }`, `{ name: "미 10년물", value: "장중 5.22%" }`. `asOf`에 무엇을 실었는지 적는다.
  - 헤드라인에 나온 숫자는 1면 표에도 있어야 한다. 본문에 쓴 값을 1면에서만 비우지 않는다.
- **change:** 반드시 부호를 붙인다. `+`는 오름(빨강), `-`는 내림(파랑)으로 표시된다.
  - 퍼센트: `"+1.37%"`
  - 금리 차: `"-0.081%p"` 또는 `"+5bp"`
  - 원화: `"+13.6"`
  - 등락을 비우는 경우: 일요일·월요일판, 휴장한 시장의 직전 거래일 값, 종가가 아니거나 기사마다 갈린 값.
- **desks:** `rates`(금리 · 시장), `energy`, `geo`, `tech`, `etc`(그 외) 순서다.
  - 데스크마다 `items`는 1~2개다.
  - 그날 소식이 없는 데스크는 통째로 뺀다.
  - `url`은 본문에 실제로 쓴 기사 링크여야 한다.
- **summary:** 그 데스크 본문의 요약이다. 1면에서 두 항목 아래에 보인다.

## 3. 본문 섹션

섹션 제목의 첫 단어로 1면 데스크 링크가 연결되므로 제목 머리를 지킨다.

| 순서 | 제목 머리 | 내용 |
|---|---|---|
| 1 | `## 3줄 요약` | 번호 목록 세 줄. 각 줄은 `**결론 문장.**` + 한두 문장 |
| 2 | `## 오늘의 숫자` | 표 `지표 | 값 | 변동` + 이탤릭 각주 한 줄 |
| 3 | `## 금리 — 부제` | 금리·환율·달러·금·경제지표 |
| 4 | `## 시장 — 부제` | 뉴욕·한국 증시, 투자자별 매매, 환율 |
| 5 | `## 에너지 — 부제` | 유가, 공급 |
| 6 | `## 지정학 — 부제` | 분쟁, 외교 |
| 7 | `## IT · 테크` | 목록. 항목마다 `**굵은 결론.**` + 설명 |
| 8 | `## 그 외` | 목록. 부동산, 기타 |
| 9 | `## 다음에 볼 것` | 목록 두세 개. 항목마다 `**무엇을 볼지 한 문장.**` + 두 칸 들여 쓴 줄 셋(갈래마다 한두 문장) |

- `## 라벨 — 부제` 형식이면 사이트에서 금색 라벨과 흰 제목으로 나뉘어 보인다.
- 소식이 없는 섹션은 뺀다.
- 섹션 끝에 해석이 필요하면 `**해설:**` 단락을 하나 둔다. IT · 테크와 그 외에는 보통 두지 않는다.
- `## 다음에 볼 것`은 1면 데스크와 연결되지 않는 섹션이라 `front.desks`에 대응 항목을 만들지 않는다. 쓰는 법은 CLAUDE.md "사이트 구조"의 다음에 볼 것 항목에 있다.
- 오늘의 숫자 표에는 1면 여섯 지표에 더해 코스닥·나스닥·다우·WTI 등을 넣어도 된다. 표에는 **값까지 확인된 행만** 넣는다. 등락률만 확인된 지표(예: "S&P 500 0.2% 상승")는 표에서 빼고 본문 문장으로 쓴다.
- 표 각주에는 기준 시점을 적는다. 정산가·브렌트·WTI처럼 용어 페이지가 있는 말은 사이트가 링크를 걸어 주므로 길게 풀지 않는다.
- D가 일요일·월요일이면 표를 만들지 않고 직전 거래일 안내 한 줄로 대신한다(CLAUDE.md "일요일·월요일판").
  예: `*새 마감이 없는 날이다. 직전 거래일(9월 18일) 마감은 [9월 19일 일일](/jogan/daily/2026-09-19/#numbers)에 있다.*`

## 4. 마크다운 규칙

- **출처:** 문장 끝 괄호 안에 매체명 링크로 단다. 예: `…했다([뉴스핌](https://…)).`
  - 한 단락을 목록으로 나누면 출처를 항목마다 단다.
  - 투자자별 매매처럼 한 기사에서 나온 짧은 숫자 목록은, 목록을 여는 앞 문장에 출처를 달면 항목마다 달지 않아도 된다. 예: `누가 사고 팔았는지는 이렇다([뉴스핌](https://…)).`
  - 기업·인물이 등장하는 문장은 그 문장에 링크를 단다. 문단 끝이나 목록 앞 문장에 몰아 달지 않는다. 바로 위의 예외도 적용하지 않는다.
  - 통신사 보도를 국내 매체가 받았으면 경로까지 밝힌다. 예: `로이터가 전했다고 [이투데이](https://…)가 보도했다.`
- **범위:** 물결표 하나 `~`를 쓴다(`3.50~3.75%`). 취소선 문제는 사이트 설정으로 막아 두었다.
- **표 부호:** 표의 등락 칸은 `+`/`-`로 시작해야 색이 입혀진다.
- **내부 링크:** 사이트 경로로 건다. 조간 글 주소는 종류별로 나뉜다.
  - 일일: `/jogan/daily/2026-09-17/#rates` (게시일)
  - 주간 흐름: `/jogan/weekly/2026-09-14/` (다루는 주의 월요일)
  - 기획 글: `/jogan/feature/iran-oil-100/` (파일 이름에서 앞 날짜를 뺀 것)
  - 그날의 1면: `/jogan/today/2026-09-17/` (1면 해설을 가리킬 때)
  - 옛 `/blog/…` 주소는 쓰지 않는다.
  - 섹션 id: `summary`, `numbers`, `rates`, `market`, `energy`, `geo`, `tech`, `etc`
- **용어 링크:** 용어 페이지(`src/content/terms/`)가 있는 말은 사이트가 처음 나오는 곳에 링크를 건다. 글쓴이가 링크를 달지 않고, 풀이도 한 줄 이하로 줄인다.
- **넣지 않는 것:** 고지문, "출처와 방법" 섹션, 목차, 편집자 고지 문장. 사이트가 알아서 붙이거나 필요 없다.

## 5. tracking.json

흐름 페이지 오른쪽 "추적 중인 흐름"이다. 지금 값은 `src/data/tracking.json`이고, 파일 전체를 D 기준으로 다시 쓴다.

```json
{
  "asOf": "2026-09-18",
  "topics": [
    { "name": "미국 장기금리", "trend": "cool", "status": "되돌림", "note": "10년물 4.939%로 다시 5% 아래, 추세 판단은 이름" }
  ]
}
```

- **trend:** `up`은 가속·확대(빨간 점), `cool`은 완화·후퇴(파란 점), `flat`은 소강(회색 점)이다.
- **status:** 두세 단어로 쓴다. **note**는 25자 안팎으로 쓴다.
- **포함 기준:** 이 글이나 이미 실린 글로 뒷받침되는 토픽만 둔다. 다이제스트 "토픽 상태 변화"는 참고만 하고 그대로 옮기지 않는다.
- **개수:** 다섯~여섯 개. 며칠째 새 소식이 없는 토픽은 `flat`으로 두거나 뺀다.
- **넣고 빼는 순서:** 새 토픽을 넣을 자리가 없으면, 가장 오래 새 소식이 없는 `flat` 토픽부터 뺀다. 그날 하루뿐인 사건은 토픽으로 올리지 않는다. 이틀 이상 이어지거나 이어질 근거가 있을 때 올린다.
- **이름 바꾸기:** 토픽의 범위가 넓어지거나 좁아지면 이름을 바꿔도 된다(예: "AI 정렬 사고 공개" → "AI 사고 공개"). desk-report에 바꾼 이유를 한 줄 남긴다.

## 6. desk-report.md

편집 단계가 무엇을 확인하고 고치고 뺐는지 남기는 문서다. 데스크 단계가 "게시 전 확인할 것"을 직접 확인하고, 토요일 주간 루틴이 "수집 지침에 알릴 것"을 모은다. 짧고 구체적으로 쓴다.

```markdown
# D 조간 데스크 리포트

**헤드라인:** …
**대조한 원문:** N건 / **실은 링크:** N개

## 원문과 달라 바로잡은 것
| 항목 | 다이제스트 | 원문 | 출처 |

## 해석을 바로잡은 것
- …

## 대체 원문으로 확인한 것
| 항목 | 원래 링크 | 못 연 이유 | 대신 확인한 주소 |
(없으면 "없음")

## 싣지 않은 것
- **링크가 첫 화면·시세 페이지:** …
- **원문에서 확인 안 됨(검색으로도 못 찾음):** …
- **날짜가 맞지 않음:** …
- **원칙상 제외(부재 보고, 전망·확률, 개인용):** …

## 수집 지침에 알릴 것
- (파이프라인에서 고쳐야 할 오류. 없으면 "없음")

## 게시 전 확인할 것
- (데스크나 사람이 판단해야 할 애매한 점. 이해 충돌 항목은 여기에 적는다. 없으면 "없음")
```
