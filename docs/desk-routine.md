# 데스크 루틴 — 매일 아침 편집·검증·발행

매일 한국 시간 09:00에 도는 예약 작업(Code 루틴)이 읽는 지침이다. 수집기(Cowork 예약 작업, 08:30)가 Drive에 남긴 다이제스트로 원고를 쓰고(편집 단계), 그 원고를 원문과 다시 대조해 싣는다(데스크 단계). 2026-10-07에 따로 돌던 Cowork 편집 예약 작업을 이 루틴에 합쳤다. 판단 기준은 `CLAUDE.md`에 있다. 편집 원칙, 글쓰기 원칙, 사이트 구조, 일요일·월요일판 규칙, 대조에서 자주 걸리는 것까지 먼저 읽고 시작한다.

이 일의 값어치는 옮기는 데 있지 않고 **검증하는 데** 있다. 수집기와 편집 단계는 매일 무언가를 틀린다. 그대로 실으면 안 된다.

**쓰는 눈과 보는 눈을 나눈다.** 편집 단계는 서브에이전트 하나가 맡고, 데스크 단계의 원문 대조는 새로 띄운 서브에이전트들이 맡는다. 대조 서브에이전트에는 원고와 링크만 주고, 편집 단계의 메모·desk-report·다이제스트는 넘기지 않는다. 쓴 맥락이 자기 글을 검증하면 관대해진다. 합치기 직전인 10/7 아침에도 데스크는 편집자가 대조를 마친 원고에서 열 곳 넘게 고쳤다. 이 루틴(메인 세션)은 원고를 직접 쓰지 않는다.

## 1. 날짜와 입력

- 날짜 D는 한국 시간 기준이다. `TZ=Asia/Seoul date +%F`로 구한다. 이 작업은 UTC로 도는 환경에서 실행되므로 그냥 `date`를 쓰면 전날이 나온다.
- Google Drive에서 `/뉴스파이프라인/daily/D/` 폴더를 찾는다. `search_files`에 `title = 'D' and mimeType = 'application/vnd.google-apps.folder'`를 넣고, `parentId = '<폴더 id>'`로 파일 목록을 본다.

**멈춰야 할 때** — 아래 경우에는 글을 만들지 말고 상황만 보고하고 끝낸다.

- `src/content/blog/D-daily.md`가 이미 있다. 덮어쓰지 않는다.
- 한국 시간 09:45까지 D 폴더나 `digest.md`가 없다. 없는 소식을 지어내지 않는다.

**수집을 기다린다.** 수집기는 대개 08:50 전후에 끝나지만 월·목(부동산 추가)에는 08:57까지 걸린 날이 있다. `digest.md`가 아직 없으면 5분씩(`sleep 300`) 기다리며 다시 본다. `digest.md`의 `modifiedTime`이 2분 안이면 2분 더 기다린다. 수집기가 분야별 로그와 정정을 이어 쓰는 중일 수 있다.

**편집 원고가 이미 있으면 편집 단계를 건너뛴다.** D 폴더에 `post.md`가 있으면(앞선 실행이 남겼거나 사람이 따로 돌린 것) 그 원고로 3단계부터 한다. 있는지는 `parentId = '<폴더 id>' and title = 'post.md'`로 따로 찾는다. 폴더 전체 목록은 결과가 길면 잘려서, 있는 파일을 없다고 본 일이 있다(10/7 시험 실행). 여러 개면 가장 늦게 만든 것을 쓴다. `download_file_content`로 받아 `/tmp/jogan/D/`에 둔다. `read_file_content`는 긴 파일의 뒤를 자르니 쓰지 않는다.

## 2. 편집 단계

서브에이전트 하나를 띄워 `docs/editor-routine.md`대로 원고를 쓰게 한다. 넘길 것은 셋뿐이다. 날짜 D, "저장소의 `docs/editor-routine.md`를 읽고 그대로 하라", 작업 폴더 `/tmp/jogan/D/`.

- 서브에이전트에 Drive 도구가 없다고 돌아오면, 메인 세션이 `digest.md`와 분야별 로그, `/뉴스파이프라인/calendar.md`를 `/tmp/jogan/D/in/`에 내려받아 두고 다시 띄운다.
- 돌아오면 `/tmp/jogan/D/`에 `post.md`·`desk-report.md`·`tracking.json`이 있는지, `post.md`가 frontmatter부터 `## 다음에 볼 것`까지 끝까지 있는지 본다. 없거나 잘렸으면 한 번 다시 띄운다. 두 번째도 실패하면 멈추고 보고한다.
- 편집 단계 보고에서 두 가지를 챙긴다. "게시 전 확인할 것"은 데스크가 직접 확인하고(3단계), "수집 지침에 알릴 것"은 최종 보고에 옮긴다.
- 편집 단계는 10분 안팎이 걸린다(10/7 시험 실행 7분, 원문 대조 4갈래는 3~4분). 그동안 메인 세션은 원고를 미리 읽거나 손대지 않는다.

## 3. 원문 대조

원고에 실린 외부 링크를 전부 연다. 분야별로 나눠 서브에이전트로 병렬 처리한다.

- **대조 서브에이전트에는 원고의 해당 섹션 문장과 링크만 준다.** 편집 단계의 desk-report, 다이제스트, 수집 로그는 주지 않는다. 같은 자료를 본 눈은 같은 곳에서 놓친다.
- 가져오기 도구는 모델 요약을 돌려준다. 그래서 "해당 내용이 담긴 문장을 원문 그대로(축약·의역 없이) 인용해 달라"고 명시해 요청하고, 돌아온 문장과 원고를 맞춘다.
- 확인할 것: 숫자, 따옴표 안 인용문(글자 단위), 날짜와 시점, 누가 말했는지, 어느 통신사가 보도했는지, 기사 입력 시각, 헤드라인·해설의 인과를 근거 기사가 실제로 말하는지.
- 같은 사실을 두 기사가 다르게 적으면 어느 쪽을 쓸지 정하고 그 기사를 링크한다. 다른 지표면 지표명을 정확히 적는다.
- 자주 걸리는 유형은 `CLAUDE.md`의 "대조에서 자주 걸리는 것"에 있다. 그것부터 찾는다.
- 근거가 없으면 문장을 뺀다. 미확인 사실을 "미확정"으로 포장하지 않는다.
- 편집 단계가 "게시 전 확인할 것"에 적은 항목은 메인 세션이 직접 확인한다.

## 4. 판 구분과 내부 링크

- D가 일요일이나 월요일이면 `CLAUDE.md`의 일요일·월요일판 규칙을 적용한다. 원고가 1면 지표에 등락을 채워 왔으면 데스크가 비운다.
- 지난 글로 거는 내부 링크는 앵커까지 실제로 있는지 확인한다. 지난 글을 고치면 `#numbers` 같은 자리가 사라질 수 있다.

## 4-2. 다음에 볼 것

일일 글은 `## 다음에 볼 것`으로 끝낸다. 규칙은 `CLAUDE.md`에 있다. 요점은 두세 개만, 본문에 이미 실린 링크된 사실에서 출발해, 전망이 아니라 확인 방법으로 쓰는 것이다.

원고에 이 섹션이 없으면 데스크가 직접 쓴다. 같은 Drive 폴더의 `digest.md` 맨 아래 "관찰 포인트"가 소재다. 그대로 옮기지 말고, 오늘 글에 링크와 함께 실린 사실에서 출발하는 항목만 남긴다. 근거가 글 안에 없으면 그 항목은 버린다.

전날 글의 이 섹션을 먼저 읽는다. 거기 적힌 항목이 오늘 확인됐으면 해당 섹션 본문에서 이어 쓴다. 이게 이어져야 매일 읽는 사람에게 흐름이 생긴다.

## 4-3. 오늘 볼 일정

원고가 1면 `front.schedule`에 오늘 일정을 한두 개 넣어 온다(규칙은 `CLAUDE.md` 사이트 구조의 "일정"). 본문 링크와 같이 확인한다.

- 줄마다 `url`을 열어 날짜와 시각이 실제로 거기 적혀 있는지 본다. 기관 공식 일정표, 직전 발표문의 다음 발표일, 회사 공식 공지만 근거다. 날마다 앞으로 밀리는 일정 페이지나 주간 전망 기사면 공식 근거로 바꾸거나 뺀다.
- `when`이 한국 시간으로 맞게 바뀌었는지 계산해 본다. 미 동부는 서머타임 동안(11월 첫 일요일까지) 13시간, 그 뒤 14시간을 더한다.
- `prev`(지난번 값)도 근거에서 확인한다. 예상치·확률이 들어 있으면 뺀다.
- 원고에 일정이 없으면 데스크가 새로 찾아 채우지 않는다. 없는 날도 있다.

## 4-4. 용어 풀이

`src/content/terms/`에 페이지가 있는 용어(10년물, 브렌트, 정산가, 순매수, PCE 등)는 본문에서 길게 풀지 않는다. 사이트가 처음 나오는 곳에 용어 페이지 링크를 자동으로 건다. 원고가 "10년물 금리는 미국 정부가 10년 만기로…"처럼 풀이 문장을 달고 왔으면 그 문장만 빼거나 한 줄 이하로 줄인다. 다른 문장은 건드리지 않는다.

## 5. 반영과 검사

`/tmp/jogan/D/post.md`를 `src/content/blog/D-daily.md`로, `tracking.json`을 `src/data/tracking.json`으로 옮긴 뒤 대조 결과대로 고친다.

```bash
python3 scripts/check_post.py src/content/blog/D-daily.md src/data/tracking.json
python3 scripts/market_check.py src/content/blog/D-daily.md
npm install --silent && npm run build && python3 scripts/linkcheck.py
```

오류는 모두 고친다. 경고는 읽어 보고 판단한다. `market_check.py`가 값이나 등락이 공식 자료와 다르다고 하면 공식 값으로 고친다. 등락은 비우지 않는다(2026-10-07 사용자 결정). "확인하지 못함"은 공식 자료가 아직 안 올라온 것이니 기사 대조 결과를 따른다. **검사를 통과하지 못하면 푸시하지 않는다.** 그날은 글을 올리지 말고 무엇이 막혔는지 보고한다. 잘못된 글이 조용히 올라가는 것보다 낫다.

## 6. 커밋과 배포 확인

- 작성자는 `barney <jp.shin.kor@gmail.com>`로 고정한다. 커밋 메시지에는 무엇을 왜 고쳤는지 적는다.
- `main`에 푸시하면 Cloudflare가 1~3분 안에 배포한다.
- 배포 확인은 **이번에 바뀐 문구**로 한다. 주소가 200을 준다는 것만으로는 옛 페이지일 수 있고, 엣지 캐시 때문에 이전 내용이 잠시 더 보인다. 예를 들어 오늘 헤드라인의 특징적인 구절을 잡아 확인한다.

```bash
for i in $(seq 1 40); do
  curl -s "https://gyeonmunrok.com/jogan/daily/D/" | grep -q '오늘만의 구절' && { echo 배포됨; break; }
  sleep 10
done
```

7분이 넘어도 확인되지 않으면 실패로 보고한다.

배포가 확인되면 새 글 주소를 IndexNow로 알린다. 네이버·빙이 검색로봇을 기다리지 않고 바로 가져간다(구글은 쓰지 않는다).

```bash
python3 scripts/indexnow.py src/content/blog/D-daily.md
```

지난 글을 정정했으면 그 글 파일도 함께 넘긴다. 실패해도 발행은 이미 끝났으니 보고에 적고 넘어간다.

## 7. 보고

- 헤드라인과 배포 확인 결과.
- 편집 단계: 다이제스트에서 바로잡은 것 가운데 큰 것, 뺀 것.
- 데스크 단계: 무엇을 고쳤는지. 항목마다 원고가 뭐라고 했고 원문이 뭐라고 했는지.
- 무엇을 싣지 않았는지와 그 이유.
- 이해 충돌: Anthropic이나 Claude가 나오는 항목은 실었든 뺐든 밝힌다. 이 데스크는 Anthropic의 모델이라 그 사안의 중립적 심판이 될 수 없다. 다른 항목과 같은 기준으로 처리하고, 판단이 갈릴 여지가 있으면 편집장이 다시 보도록 남긴다. 본문에는 편집자 고지 문장을 달지 않는다(2026-09-30 사용자 결정). 원고에 "이 글을 쓰는 편집자는 Anthropic의 모델이다" 같은 문장이 있으면 뺀다.
- 수집 지침에 알릴 것: 편집 단계가 적은 것과 데스크가 본 반복 오류.
- 이미 실린 지난 글에 정정이 필요해 보이는 것(편집 단계가 찾았어도 데스크가 고치지 않았으면 그대로 남긴다).
