# 데스크 루틴 — 매일 아침 검증·발행

매일 한국 시간 09:30에 도는 예약 작업이 읽는 지침이다. 판단 기준은 `CLAUDE.md`에 있다. 편집 원칙, 글쓰기 원칙, 사이트 구조, 일요일·월요일판 규칙, 대조에서 자주 걸리는 것까지 먼저 읽고 시작한다.

이 일의 값어치는 옮기는 데 있지 않고 **검증하는 데** 있다. 수집기와 편집자는 매일 무언가를 틀린다. 그대로 실으면 안 된다.

## 1. 날짜와 입력

- 날짜 D는 한국 시간 기준이다. `TZ=Asia/Seoul date +%F`로 구한다. 이 작업은 UTC로 도는 환경에서 실행되므로 그냥 `date`를 쓰면 전날이 나온다.
- Google Drive에서 `/뉴스파이프라인/daily/D/` 폴더의 `post.md`, `desk-report.md`, `tracking.json`을 읽는다. `search_files`로 제목이 `post.md`인 최근 파일을 찾고 `createdTime`이 오늘인지 확인하면 폴더를 특정할 수 있다. 본문이 길면 읽기 도구가 뒤를 자를 수 있으니 끝까지 왔는지 확인한다.
- `desk-report.md`에는 편집자가 남긴 "게시 전 확인할 것"이 있다. 여기에 적힌 항목은 반드시 직접 확인한다.

**멈춰야 할 때** — 아래 경우에는 글을 만들지 말고 상황만 보고하고 끝낸다.

- 오늘 폴더나 `post.md`가 없다. 없는 소식을 지어내지 않는다.
- `src/content/blog/D-daily.md`가 이미 있다. 덮어쓰지 않는다.

## 2. 원문 대조

원고에 실린 외부 링크를 전부 연다. 분야별로 나눠 서브에이전트로 병렬 처리하면 빠르다.

- 가져오기 도구는 모델 요약을 돌려준다. 그래서 "해당 내용이 담긴 문장을 원문 그대로(축약·의역 없이) 인용해 달라"고 명시해 요청하고, 돌아온 문장과 원고를 맞춘다.
- 확인할 것: 숫자, 따옴표 안 인용문(글자 단위), 날짜와 시점, 누가 말했는지, 어느 통신사가 보도했는지, 기사 입력 시각.
- 같은 사실을 두 기사가 다르게 적으면 어느 쪽을 쓸지 정하고 그 기사를 링크한다. 다른 지표면 지표명을 정확히 적는다.
- 자주 걸리는 유형은 `CLAUDE.md`의 "대조에서 자주 걸리는 것"에 있다. 그것부터 찾는다.
- 근거가 없으면 문장을 뺀다. 미확인 사실을 "미확정"으로 포장하지 않는다.

## 3. 판 구분과 내부 링크

- D가 일요일이나 월요일이면 `CLAUDE.md`의 일요일·월요일판 규칙을 적용한다. 편집자가 규칙을 모르고 1면 지표에 등락을 채워 보낼 수 있다. 그때는 데스크가 비운다.
- 지난 글로 거는 내부 링크는 앵커까지 실제로 있는지 확인한다. 지난 글을 고치면 `#numbers` 같은 자리가 사라질 수 있다. 편집자는 드라이브에 있는 옛 원고를 보므로 이 변화를 모른다.

## 4. 반영과 검사

```bash
python3 scripts/check_post.py src/content/blog/D-daily.md src/data/tracking.json
npm install --silent && npm run build && python3 scripts/linkcheck.py
```

오류는 모두 고친다. 경고는 읽어 보고 판단한다. **검사를 통과하지 못하면 푸시하지 않는다.** 그날은 글을 올리지 말고 무엇이 막혔는지 보고한다. 잘못된 글이 조용히 올라가는 것보다 낫다.

## 5. 커밋과 배포 확인

- 작성자는 `barney <jp.shin.kor@gmail.com>`로 고정한다. 커밋 메시지에는 무엇을 왜 고쳤는지 적는다.
- `main`에 푸시하면 Cloudflare가 1~3분 안에 배포한다.
- 배포 확인은 **이번에 바뀐 문구**로 한다. 주소가 200을 준다는 것만으로는 옛 페이지일 수 있고, 엣지 캐시 때문에 이전 내용이 잠시 더 보인다. 예를 들어 오늘 헤드라인의 특징적인 구절을 잡아 확인한다.

```bash
for i in $(seq 1 40); do
  curl -s "https://gyeonmunrok.com/jogan/daily/D/" | grep -q '오늘만의 구절' && { echo 배포됨; break; }
  sleep 10
done
```

7분이 넘어도 확인되지 않으면 실패로 보고한다.

## 6. 보고

- 무엇을 고쳤는지: 항목마다 원고가 뭐라고 했고 원문이 뭐라고 했는지.
- 무엇을 싣지 않았는지와 그 이유.
- 이해 충돌: Anthropic이나 Claude가 나오는 항목은 실었든 뺐든 밝힌다. 이 데스크는 Anthropic의 모델이라 그 사안의 중립적 심판이 될 수 없다. 다른 항목과 같은 기준으로 처리하고, 판단이 갈릴 여지가 있으면 편집장이 다시 보도록 남긴다.
- 수집기나 편집자에게 알릴 만한 반복 오류.
